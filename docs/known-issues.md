# Известные ограничения и открытые задачи

## Не реализовано

- **Похожие и перекодированные видео.** Нужен внешний `ffmpeg.exe` (по аналогии с `fpcalc` для
  аудио). Сейчас видео находятся только как точные копии (`MatchType.ExactVideo`).
- **RAW/HEIC.** Такие файлы распознаются как изображения (`CategoryDetector`) и участвуют в поиске
  точных копий, но превью и pHash для них требуют нативных декодеров (libheif и т. п.).
- **Распределение результатов** умеет только отчёт CSV и копирование (`DistributionMode.ReportOnly`,
  `CopyFiles`). Перемещение и ярлыки сознательно не реализованы: оригиналы не трогаются.
- **Сторожевой режим** работает, только пока приложение открыто (`FileSystemWatcher` внутри
  процесса); фоновой службы нет.
- Мультиязычный интерфейс, облачная индексация и синхронизация не входят в текущую версию.

## Ограничения текущей реализации

- **USN-журнал версии 3** (128-битные FRN) не разбирается: при такой записи MFT-обход откатывается
  на Win32Find, а USN-дельта — на полный пересбор тома. Данные не теряются, но повторный скан
  медленнее.
- **Проверка стабильности файла во время скана** сравнивает только длину до и после чтения.
  Файл, изменённый без смены размера, ловится обязательной побайтовой сверкой и перепроверкой
  перед удалением, поэтому ложного удаления не будет, но хэш такого файла может оказаться устаревшим
  до следующего скана.
- **Список результатов не виртуализирован** на уровне XAML (`ItemsControl`). Память ограничена
  постраничной загрузкой групп из базы (`GroupRepository.GetGroupsPage`) и ленивыми миниатюрами;
  на очень больших страницах прокрутка может быть тяжелее.
- **Сетевые носители и NAS** сканируются в совместимом режиме (`Win32FindNetwork`); скорость
  зависит от сети. Корзины на таких томах нет, удаление идёт в карантин.
- **Замена дубликатов жёсткими ссылками** доступна только в пределах одного тома NTFS.
- **Аудио-сверка** требует внешнего `fpcalc.exe` (Chromaprint); без него пункт «Похожая музыка»
  недоступен.

## Не проверено автоматически

- Пути, требующие прав администратора и реального NTFS: MFT-перечисление через
  `Deduplicator.MftHelper`, `FSCTL_READ_USN_JOURNAL`, восстановление путей через `OpenFileById` и
  сквозной путь `ScanService` → USN-дельта. Юнит-тесты покрывают разбор и планирование на
  подготовленных данных; при любом сбое в рантайме эти вызовы деградируют в полный пересбор.
- Замеры производительности на эталонных носителях (USB2-флешка, USB3-SSD, внешний HDD, корпуса
  100 тыс. и 1 млн файлов) не зафиксированы. Харнесс для них есть: `tools/DedupBench`.
- Около 50 тестов `tests/Deduplicator.Core.Tests` используют Win32/NTFS/буквы дисков и проходят
  только на Windows.

## Возможные улучшения

- Однопроходная воронка «сравнение + хэш» для случаев, когда полный хэш доминирует в профиле.
- Небуферизованное чтение (`FILE_FLAG_NO_BUFFERING`) для больших файлов на внутренних NTFS-дисках.
- Treemap занятого места.
- Несохранённые изменения в настройках: предупреждение при уходе со страницы.

## Заметка для сборки

Lock-файлы NuGet (`packages.lock.json`) сформированы для Debug-оценки проектов
(`Avalonia.Diagnostics` подключается только в Debug). Перед Release-сборкой выполняйте
`dotnet restore Deduplicator.slnx --locked-mode`, а затем `dotnet build -c Release --no-restore`;
неявный restore в Release перепишет `tests/Deduplicator.App.Tests/packages.lock.json`.
